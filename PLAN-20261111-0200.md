## Approach

### Strategy
1. **Create project-local workflows** in `careeros/.pi/workflows/` (highest precedence)
2. **Use TypeScript workflow files** for type safety and IDE support
3. **Leverage existing agent instructions** - workflows will read agent files for prompts
4. **Enforce approval checkpoints** using `humanDecision` for external actions
5. **Use compute nodes** for file I/O operations (reading/writing CSV and Markdown)
6. **Keep workflows simple** - each workflow does one thing well
7. **Share data** - all workflows read/write to the same CareerOS files

### Key Design Decisions

| Decision | Rationale |
|----------|-----------|
| Use `.pi/workflows/` in project | Highest precedence, portable with project |
| TypeScript workflow files | Type safety, better error messages, IDE support |
| Read agent files at runtime | Keep prompts maintainable in one place |
| humanDecision for approvals | Enforces user approval before external actions |
| compute nodes for file I/O | Deterministic operations, no agent needed |
| Consistent file paths | All workflows use relative paths from project root |

### Alternatives Considered
- **Global workflows:** Rejected - want portability with project
- **Single monolithic workflow:** Rejected - better to have 6 focused workflows
- **Custom file formats:** Rejected - use existing CareerOS CSV/Markdown
- **Automatic execution:** Rejected - always require explicit user approval

### Workflow Files

#### 1. find-opportunities.workflow.ts
**Purpose:** Find relevant companies and people for outreach
**Nodes:**
- `read_targets`: compute - Read TARGETS.md to get search criteria
- `read_existing`: compute - Read existing companies.csv and people.csv
- `find_companies`: agent - Use Researcher agent to find companies
- `find_people`: agent - Use Researcher agent to find people (founders, HR, recruiters, hiring managers, alumni)
- `deduplicate`: compute - Remove duplicates from existing records
- `save_results`: compute - Add new entries to CSV files
- `report`: compute - Generate summary report

**Approval Checkpoints:** None (read-only research)

#### 2. research-contact.workflow.ts
**Purpose:** Research a specific person for outreach
**Input:** `{ personId?: string, name?: string, company?: string }`
**Nodes:**
- `validate_input`: compute - Validate input and check existing records
- `read_profile`: compute - Read PROFILE.md for user context
- `research_person`: agent - Use Researcher agent to gather info
- `identify_connections`: compute - Find connection points with user
- `save_research`: compute - Save to people.csv and records/
- `report`: compute - Generate research report

**Approval Checkpoints:** None (read-only research)

#### 3. cold-outreach.workflow.ts
**Purpose:** Create personalized cold outreach messages
**Input:** `{ personId: string }` or `{ contactId: string }`
**Nodes:**
- `validate_person`: compute - Check person exists in people.csv
- `read_research`: compute - Read research from records/ if available
- `read_profile`: compute - Read PROFILE.md and PROOF.md
- `create_message`: agent - Use Outreach agent to draft message
- `approval_checkpoint`: humanDecision - **REQUIRED: User must approve message**
- `save_draft`: compute - Save draft to records/messages/
- `update_outreach_csv`: compute - Add entry to outreach.csv with status=pending
- `report`: compute - Confirm draft saved, awaiting approval

**Approval Checkpoints:** 
- `approval_checkpoint`: humanDecision with choices: approve, revise, cancel

#### 4. job-application.workflow.ts
**Purpose:** Prepare and track job applications
**Input:** `{ jobId?: string, url?: string, company?: string }`
**Nodes:**
- `validate_input`: compute - Validate input
- `read_profile`: compute - Read PROFILE.md and PROOF.md
- `read_job_desc`: agent - Extract requirements from job description
- `evaluate_fit`: compute - Compare requirements to user profile
- `prepare_materials`: agent - Use Application agent to tailor CV/cover letter
- `approval_checkpoint`: humanDecision - **REQUIRED: User must approve submission**
- `save_materials`: compute - Save to records/jobs/
- `update_jobs_csv`: compute - Add/update entry in jobs.csv
- `report`: compute - Confirm application prepared, awaiting submission

**Approval Checkpoints:**
- `approval_checkpoint`: humanDecision with choices: approve, revise, cancel

#### 5. interview-prep.workflow.ts
**Purpose:** Prepare for interviews
**Input:** `{ jobId: string }` or `{ companyId: string, role: string }`
**Nodes:**
- `validate_input`: compute - Validate job exists
- `read_job_desc`: compute - Read job description from records/jobs/
- `read_profile`: compute - Read PROFILE.md and PROOF.md
- `analyze_requirements`: agent - Use Interview Coach to identify gaps
- `generate_questions`: agent - Generate technical and behavioral questions
- `create_study_plan`: agent - Create personalized study plan
- `save_study_plan`: compute - Save to study.csv and records/jobs/
- `report`: compute - Present study plan

**Approval Checkpoints:** None (read-only preparation)

#### 6. daily-career.workflow.ts
**Purpose:** Daily career management routine
**Nodes:**
- `read_state`: compute - Read all CSV files and TARGETS.md
- `check_followups`: compute - Identify pending follow-ups from outreach.csv
- `check_deadlines`: compute - Identify application deadlines from jobs.csv
- `suggest_outreach`: agent - Use Manager to suggest 3 people to contact
- `suggest_applications`: agent - Use Manager to suggest 2 jobs to apply to
- `suggest_study`: agent - Use Manager to suggest study topics
- `generate_report`: compute - Create daily report
- `save_report`: compute - Save to records/daily-[date].md
- `present_report`: compute - Display report to user

**Approval Checkpoints:** None (read-only suggestions)

## Risks & Open Questions

### Risks
1. **File Path Issues:** Workflows need consistent relative paths from project root
   - *Mitigation:* Use `process.cwd()` or require workflows to run from `careeros/` directory

2. **CSV Parsing:** Need to handle CSV headers and empty files correctly
   - *Mitigation:* Use a CSV parsing library or simple string parsing for known formats

3. **TypeScript in Workflows:** Need to ensure TypeScript works without build step
   - *Mitigation:* pi-workflows uses jiti for runtime TypeScript compilation

4. **Approval Checkpoint Fatigue:** Too many approvals could slow down workflow
   - *Mitigation:* Only require approval for external actions (sending messages, submitting applications)

5. **State Consistency:** Multiple workflows modifying same files could cause conflicts
   - *Mitigation:* Use atomic file writes, document that workflows should not run concurrently

### Open Questions
1. **Should workflows be in project or global directory?**
   - *Decision:* Project directory for portability

2. **How to handle file locks for concurrent access?**
   - *Decision:* Document single-user usage, no concurrent workflow runs

3. **Should we add a workflow to initialize CareerOS?**
   - *Decision:* No, keep it simple. User manually completes PROFILE.md, PROOF.md, TARGETS.md

4. **How to handle errors in workflows?**
   - *Decision:* Use try/catch in compute nodes, return error states

5. **Should workflows validate CSV format before writing?**
   - *Decision:* Yes, validate format in compute nodes
